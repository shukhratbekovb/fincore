История проведённых движений одного своего кошелька. Отсутствующий/чужой кошелёк даёт 404, свой без движений — пустую страницу. Читаются все статусы кошелька, включая frozen/closed. source_type и source_id связывают journal с переводом или пополнением. Направление относительно выбранного кошелька: incoming или outgoing. При пополнении counterparty_wallet_id и sender_wallet_id равны null. INTERNAL для одного кошелька недопустим. Фильтры kind, currency, direction и [posted_from, posted_to).

Требуется Bearer access JWT и активный пользователь. Денежные значения новых финансовых ответов сериализуются десятичными строками minor units; вход amount_minor принимает целое JSON-число или строку цифр, без bool/float. Валюта задаётся явно. Даты содержат timezone. Ответы, включая ожидаемые ошибки, имеют Cache-Control: no-store. Ошибки используют общий detail.code/message/errors; SQL и секреты не раскрываются.

Пагинация: limit=20, максимум 100. Порядок время DESC, journal/transfer ID DESC. Cursor подписан, связан с actor, query и фильтрами; можно менять limit. Пустая/последняя страница имеет next_cursor=null. Неверный cursor или изменённые фильтры дают 422. Каждый SQL-запрос повторно ограничивает owner scope. Cursor не фиксирует snapshot между HTTP-страницами.
