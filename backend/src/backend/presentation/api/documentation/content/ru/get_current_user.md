Передайте `Authorization: Bearer <access_token>`. Сервер проверит подпись JWT, issuer, audience, назначение и срок действия, затем загрузит пользователя по UUID из sub. Указывать user_id в URL, query или JSON не нужно: такие значения не выбирают другого пользователя. Неактивный аккаунт получает `403`, отсутствующий — `404`.

При успехе возвращается `200` с id, username, email и created_at. Username и email представлены строками. Хеш пароля и токены не входят в ответ. Дата содержит часовой пояс. Ответ имеет `Cache-Control: no-store`. Текущая авторизация проверяет JWT и статус пользователя; отзыв сессий пока не делает ранее выданный access JWT недействительным до его истечения.
