Обменивает текущий refresh-токен на новый access-токен и заменяющий refresh-токен.
Исходный идентификатор и абсолютный срок сессии сохраняются: refresh не продлевает сессию.
Последние IP и необязательный User-Agent обновляются, исходные метаданные входа остаются прежними.

```bash
curl -X POST http://127.0.0.1:8000/v1/auth/refresh \
  -H 'Content-Type: application/json' \
  -H 'User-Agent: FinCoreDocs/1.0' \
  -d '{"refresh_token":"example-refresh-token"}'
```

После `200` замените оба сохранённых токена полученными значениями. Использованный refresh-токен
больше нельзя применять для обновления. Если повторить его при действующей сессии, сервер отзовёт
сессию и вернёт `401 invalid_refresh_token`. Тот же код возвращается для неизвестных, истёкших
и отозванных токенов/сессий. Неактивный аккаунт даёт `403 user_inactive`.

**Для одной сессии допускайте только один выполняющийся refresh-запрос.** Параллельный запрос
или автоматический повтор после неоднозначного сетевого сбоя может считаться повторным использованием
и отозвать сессию. Ключа идемпотентности и периода допуска повторов нет.
Если актуальный действующий refresh-токен недоступен, выполните вход заново.
