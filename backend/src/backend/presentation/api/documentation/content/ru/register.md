Создаёт пользователя со статусом `pending_confirmation`. Username и email приводятся к нижнему регистру.
Оба значения должны быть уникальными. На этом шаге пароль не принимается и не генерируется.

Одноразовое подтверждение и задание на его доставку сохраняются вместе с пользователем.
Ответ `201` содержит только `user_id`: он не возвращает токены и не гарантирует доставку письма.
Для доставки должен быть запущен отдельный outbox worker и настроен SMTP. Срок подтверждения
настраивается, по умолчанию это один час.

```bash
curl -X POST http://127.0.0.1:8000/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"username":"alice","email":"alice@example.com"}'
```

После получения токена через сценарий доставки выполните `POST /v1/auth/confirm`.
Повторная регистрация с тем же username/email вернёт `409` и не отправит подтверждение повторно.
Для новой ссылки используйте `POST /v1/auth/confirm/resend` с email. Общий ответ `202` не раскрывает статус аккаунта.

Redis ограничивает попытки регистрации: по умолчанию 10 запросов в час на IP и 3 в час на email, включая конфликты регистрации. Email нормализуется так же, как в домене. Смена IP не сбрасывает бюджет email. Настройки REGISTER_RATE_LIMIT_IP_PER_HOUR и REGISTER_RATE_LIMIT_EMAIL_PER_HOUR. IP требуется даже при регистрации.

При превышении любого бюджета возвращается `429` с `Retry-After`. При недоступности Redis — `503 rate_limiter_unavailable`, use case не выполняется.

Новое письмо подтверждения инвалидирует предыдущие регистрационные ссылки.
