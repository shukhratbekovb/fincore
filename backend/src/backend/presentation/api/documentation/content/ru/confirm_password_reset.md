Передайте только `token` из письма в JSON. Пароль генерируется сервером; прислать собственный пароль нельзя. GET по ссылке ничего не меняет: frontend читает fragment, убирает токен из адресной строки и выполняет POST только после явного подтверждения пользователя. Используйте HTTPS и страницу без сторонних скриптов/аналитики.

После успешной транзакции возвращается `200 {"password": "..."}` с `Cache-Control: no-store`. Покажите пароль один раз и предложите сохранить его. Не отправляйте ответ в логи, аналитику или долговременное browser-хранилище. Если ответ потерян, повторите весь сброс с новой ссылкой: старый токен уже использован.

Одновременно отзываются все сессии и оставшиеся reset-ссылки пользователя; в outbox попадает уведомление без пароля. Войти нужно отдельно через login. Выданные access JWT продолжают действовать до истечения срока. Любой неизвестный, использованный, истёкший токен, другое назначение или неподходящий аккаунт дают одинаковый `400 invalid_password_reset_token`. Лимит — 20 запросов в минуту на IP; `429` содержит `Retry-After`.

Лимиты проверяются через общий Redis. При его недоступности возвращается `503 rate_limiter_unavailable`; операция не выполняется.
