Проверяет учётные данные и создаёт отдельную сессию при каждом успешном входе.
Возвращает access JWT и непрозрачный refresh-токен в JSON. Cookies авторизации не устанавливаются.

Существующий пароль проверяется без изменений, с ограничением длины 1–256 символов.
Требования к сложности нового пароля здесь не применяются, чтобы аккаунты со старыми паролями могли войти.
Неизвестный username, отсутствие пароля у аккаунта и неверный пароль возвращают одинаковую ошибку
`401 invalid_credentials`. Неактивный аккаунт даёт `403 user_inactive` после проверки верного пароля.

```bash
curl -X POST http://127.0.0.1:8000/v1/auth/login \
  -H 'Content-Type: application/json' \
  -H 'User-Agent: FinCoreDocs/1.0' \
  -d '{"username":"alice","password":"ExamplePassword1!"}'
```

IP клиента и необязательный User-Agent сохраняются как метаданные сессии. Они определяются по
соединению/доверенному прокси и заголовку, а не по JSON-полям. Разные входы создают разные сессии.
Сроки по умолчанию: 30 минут для access-токена и 30 дней для сессии; настройки развёртывания могут их менять.
Сохраните полученный refresh-токен для последующих вызовов refresh/logout.

Redis ограничивает все попытки входа, включая успешные и неверный пароль: по умолчанию 30 запросов в минуту на IP и 10 на нормализованный username, независимо от существования аккаунта. Смена IP не сбрасывает бюджет username; регистр букв не создаёт новый бюджет. Настройки LOGIN_RATE_LIMIT_IP_PER_MINUTE и LOGIN_RATE_LIMIT_USERNAME_PER_MINUTE. Это временное окно, не постоянная блокировка аккаунта.

При превышении любого бюджета возвращается `429` с `Retry-After`. При недоступности Redis — `503 rate_limiter_unavailable`, use case не выполняется.
