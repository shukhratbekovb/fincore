Требует Bearer access JWT и активного пользователя. GET не принимает JSON-тело. Возвращается `200` с массивом собственных кошельков и их балансами. Отсутствие кошельков или совпадений с фильтром даёт `[]`. user_id всегда берётся из JWT и не может быть изменён параметрами запроса.

Необязательные query-параметры: currency, status, sort_by. Например: `/v1/wallets?currency=CAD&status=active&sort_by=balance:desc`. Без status включаются все статусы, включая closed. По умолчанию сортировка created_at:asc, при равных значениях — id ASC. Поля сортировки: name, currency, balance, created_at, status; направления asc/desc. Сортировка balance сравнивает значения minor без пересчёта валют. Неверные значения enum дают `422`.

Каждый кошелёк и его баланс читаются одним общим SQL-запросом без N+1, row locks и commit. Отсутствие balance у собственного кошелька приводит к `500 wallet_accounting_state_error`, а не к нулю или пропуску записи. Возвращается весь отфильтрованный список; пагинация пока отсутствует. Ответ имеет `Cache-Control: no-store`.
