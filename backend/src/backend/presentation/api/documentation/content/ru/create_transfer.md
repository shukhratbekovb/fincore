Создаёт перевод между разными кошельками одной валюты. Actor определяется JWT и должен владеть кошельком отправителя. Оба кошелька и их счета должны разрешать операцию. Перевод, две проводки, обе проекции баланса и результат идемпотентности фиксируются одним commit. Обязателен заголовок Idempotency-Key. Тот же ключ и payload возвращают прежний transfer_id с 201; изменение payload даёт 409. Конкурирующий ключ ожидается до 2 секунд, затем возможен 409 idempotency_in_progress. Отказы откатываются без сохранения REJECTED. Успешный ответ возвращается только после commit.

Требуется Bearer access JWT и активный пользователь. Денежные значения новых финансовых ответов сериализуются десятичными строками minor units; вход amount_minor принимает целое JSON-число или строку цифр, без bool/float. Валюта задаётся явно. Даты содержат timezone. Ответы, включая ожидаемые ошибки, имеют Cache-Control: no-store. Ошибки используют общий detail.code/message/errors; SQL и секреты не раскрываются.

Redis ограничивает POST-запросы создания перевода: по умолчанию 30 в минуту на пользователя из JWT и 100 в минуту на IP. Общий бюджет пользователя охватывает все кошельки и Idempotency-Key. Повтор уже выполненного перевода также расходует HTTP-бюджет и может получить 429; после освобождения бюджета повторите тот же ключ и payload. Идемпотентность предотвращает повторное списание. Настройки TRANSFER_RATE_LIMIT_USER_PER_MINUTE и TRANSFER_RATE_LIMIT_IP_PER_MINUTE. JWT и обязательный заголовок проверяются до расходования бюджета; GET-маршруты переводов этим правилом не ограничены.

При превышении любого бюджета возвращается `429` с `Retry-After`. При недоступности Redis — `503 rate_limiter_unavailable`, use case не выполняется.
