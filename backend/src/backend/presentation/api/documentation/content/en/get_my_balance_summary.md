Aggregates all owned wallets in one SQL snapshot independently of wallet-list pagination. posted/available include active, frozen and closed wallets; spendable includes only active wallets. Totals stay separate per currency. Optional currency narrows the selection. No matching wallets gives totals=[]; real zero wallets retain zero totals. Missing accounting projections return integrity error 500. Aggregate sums may exceed a single BIGINT and are never truncated.

Requires a Bearer access JWT and an active user. Monetary fields in these new financial responses are decimal minor-unit strings. Request amount_minor accepts a JSON integer or digit string, never bool/float. Currency is explicit. Timestamps are timezone-aware. Responses including expected errors use Cache-Control: no-store. Errors use the shared detail.code/message/errors envelope without SQL details or secrets.
