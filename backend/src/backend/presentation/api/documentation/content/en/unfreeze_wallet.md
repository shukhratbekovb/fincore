Unfreeze a wallet owned by the authenticated active user. Supply the wallet UUID in the path; no request body is required. This operation is exclusively an owner action. It does not grant administrator or operator powers, and cannot undo an administrative block because administrative freezes are not supported by this MVP.

The response is `204` with no body and `Cache-Control: no-store`. The wallet becomes `active`. Repeating the same request succeeds without changing timestamps again. A closed wallet returns `409 wallet_closed`; foreign and absent wallets both return `404 wallet_not_found`. A missing balance or invalid liability account returns a controlled `500 wallet_accounting_state_error` without changing state.

The active user is rechecked under a row lock, followed by wallet, balance and ledger-account locks in the posting order. The balance, journal and active liability account are preserved. A frozen wallet rejects both incoming and outgoing new transfers and sandbox top-ups, while its balance and history remain readable. Unfreezing allows new money operations again. A successful replay of an already completed idempotent transfer does not post additional money even if the wallet has since been frozen.
