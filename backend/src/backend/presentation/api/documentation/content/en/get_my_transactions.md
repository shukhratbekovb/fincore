Combined posted journal history across owned wallets; no PENDING/REJECTED attempts. An own-wallet transfer appears once as internal. Selecting wallet_id changes direction to incoming/outgoing relative to that owned wallet; combining wallet_id with internal is invalid. Foreign/missing wallet filters yield empty pages. Top-ups are incoming. kind, currency, direction and [posted_from, posted_to) apply server-side before pagination.

Requires a Bearer access JWT and an active user. Monetary fields in these new financial responses are decimal minor-unit strings. Request amount_minor accepts a JSON integer or digit string, never bool/float. Currency is explicit. Timestamps are timezone-aware. Responses including expected errors use Cache-Control: no-store. Errors use the shared detail.code/message/errors envelope without SQL details or secrets.

Pagination defaults to 20, maximum 100. Order is timestamp DESC then journal/transfer ID DESC. Signed cursor binds actor, query and filters; page size may change. Final/empty pages have next_cursor=null. Invalid cursor or changed filters return 422. SQL applies ownership on every request. A cursor does not preserve a snapshot across HTTP pages.
