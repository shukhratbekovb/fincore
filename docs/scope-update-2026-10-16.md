# Согласованное изменение scope — 16 октября 2026

Статус: согласовано пользователем в обсуждении. Этот документ изменяет исходную baseline PRD v1.0; исходный PDF сохраняется как исторический документ. Реализация и миграции ещё не выполнены.

## Продуктовые решения

1. Пять основных разделов: **Главная → Кошельки → Перевод → История → Профиль**.
2. На телефоне пять пунктов нижней навигации, Перевод по центру; на desktop те же разделы в боковом меню.
3. Несколько самостоятельных CAD-кошельков пользователя, представленных карточками с названием, балансом, валютой и цветом. На телефоне карточки главной листаются горизонтально; на desktop показаны сеткой. Полный список доступен в Кошельках.
4. Главная показывает общий баланс CAD, кошельки, быстрый перевод и последние операции.
5. Перевод — самостоятельная страница с выбором source wallet, получателя и суммы. Два сценария: другому пользователю по wallet ID и между своими разными кошельками. Быстрые действия открывают эту страницу с предвыбранным source.
6. История объединяет операции с фильтром по кошельку.
7. Профиль содержит данные пользователя, настройки оформления и выход. Редактирование личных данных и расширенные настройки безопасности не входят автоматически в это решение.
8. Адаптивность для телефона и desktop обязательна. Светлый/тёмный концепты — ориентиры; финальный набор цветов и язык ещё не выбран.

## Изменения backend/API

- Снять ограничение UNIQUE(user_id,currency) с Wallet; сохранить UUID PK и отдельные Balance/LIABILITY account каждого wallet. Один пользователь может иметь несколько CAD wallets.
- Создание второго wallet — штатный сценарий, не WALLET_EXISTS. Политику защиты создания от повторной доставки согласовать отдельно.
- Название и цвет требуют полей хранения и API-схем; длина, палитра, defaults и изменение metadata ещё не определены.
- Перевод между своими кошельками использует те же атомарные проводки и idempotency. Запрещён source_wallet_id == destination_wallet_id, а не одинаковый owner.
- Общий баланс и общая история требуют согласованного API. Не получать общий баланс из неполной страницы wallets и не склеивать отдельные cursor pages в глобальную историю на клиенте.
- В общей истории внутренний перевод отображать одной бизнес-операцией с двумя кошельками; в истории каждого wallet — соответствующее входящее/исходящее движение. Общая сумма средств пользователя при таком переводе неизменна.

## Открытые детали реализации

Лимит количества кошельков; поля metadata и их редактирование; защита создания от дублей; включение FROZEN/CLOSED в общий баланс; snapshot общего баланса; контракт единой истории и wallet filter; хранение выбора темы. Эти вопросы не отменяют согласованную структуру и фиксируются до интеграции.

## Проверка

Создать два CAD wallets одному user с независимыми нулевыми balances/accounts. Пополнить первый на 500 CAD и перевести 100 CAD во второй: остатки 400/100, общий итог 500, один journal и одна операция общей истории. Повтор с тем же ключом не создаёт новое движение. Перевод в тот же wallet отклоняется. Проверить пять разделов на mobile/desktop, карточки и фильтрацию.
